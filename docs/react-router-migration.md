# React Router migration decisions

Migration branch: `feat/react-router-writing-api`, based on `develop`. The initial
implementation was prepared for review; the user subsequently authorized commit,
push and a pull request targeting `develop`. Merge and deployment remain separate
release actions.

## Version and runtime

The implementation targets the latest stable release verified for this migration,
React Router **8.4.0**, with matching `@react-router/dev`. The initial request named
v7; the current implementation follows the subsequently selected stable version.
React Router Framework Mode supplies route modules, loader data, metadata, generated
route types and Vite builds. Cloudflare's Vite plugin builds the Worker directly;
Next.js, OpenNext and React Server Component conventions are removed.

The independent admin uses a second Vite build and browser routing. It shares
feature components and API contracts without importing server modules. The Worker
serves its static shell and authenticated APIs separately from the public SSR handler.
This deliberate split avoids assuming that declaring a Client Component or using
React Router globally with SSR enabled makes admin server rendering disappear.

## SEO and client rendering

Home, resume, tech-stack and published article detail keep server-rendered useful
content and metadata. Home's recent-writing section and writing list/tag/search/
series cards fetch through the public API and render in the browser. Public shells
retain shared navigation and page metadata. Loading/error/empty states are explicit.
The private admin and signed draft preview do not need SEO SSR.

Published article loaders use public-only reads and sanitized rendered HTML; drafts
are 404 through ordinary public reads. The separate preview API verifies a bounded,
expiring signature for the requested slug before querying and returns sanitized HTML
without persistent caching. Server authorization and document validation remain in
place for every mutation.

## Data fetching

TanStack Query manages client cache, loading, error and mutation lifecycle. Ky is
its same-origin HTTP transport. Default query stale time is one minute; automatic
retries and focus refetch are disabled. Session freshness is explicit. Writes are
not retried, and affected query keys are invalidated after successful changes.
No polling or speculative route data prefetch is added.

Public server data/render caching keeps existing KV/D1 resources with a new cache
namespace and D1 revision keys. The retained binding and public-environment names
avoid a remote configuration migration while their implementation becomes independent
of Next.js. See [cache/CPU guidance](worker-cpu-optimization.md).

## Review and validation

Review route output without JavaScript for SEO pages, confirm public cards use APIs,
and confirm admin document loads never invoke the public SSR tree. Check draft
isolation, preview signatures, mutation Origin/size validation, session expiration,
cache invalidation and existing authoring interactions. Unit tests, isolated SQL
tests, production build and Workerd browser tests verify different boundaries;
report their results and skipped cases separately.

No migration test proves every Worker request stays below the free-plan CPU ceiling.
An approved dev deployment and CPU profiling are still required for that conclusion.
Historical Next/OpenNext reports are retained in `docs/history` as evidence of earlier
investigations, not current setup instructions.

### Final local validation — 2026-10-09

- `npm run check`: formatting, lint and generated route types/TypeScript pass;
  288 unit tests pass across 39 files.
  Ignored Worker types are regenerated by the check command; this was verified
  after removing the generated file. Wrangler's runtime types replace the
  redundant `@cloudflare/workers-types` package.
- Isolated localhost Neon HTTP/Postgres integration: 13 tests pass, including
  query budgets and transaction rollback. Local proxy bootstrap works on an
  existing disposable Docker volume.
- Final Workerd browser projects, run separately with one worker and no retries:
  133 public/read tests and 23 admin/write tests pass. One optional configured-R2
  control test is skipped because this fixture does not provide R2. Authoring,
  signed preview, publish/unpublish/delete, logout revocation, cross-origin
  rejection, SEO without JavaScript and client-only cards are exercised.
- Default and `CLOUDFLARE_ENV=dev` production builds and Wrangler deployment
  **dry-runs** pass. Each selects its existing isolated KV/D1 bindings. Worker
  gzip upload is about 2,705 KiB (2.64 MiB), below the documented 3 MiB free-plan
  bundle limit; that is a packaging check, not a CPU measurement.
- Development smoke: home, admin login and admin JavaScript assets return 200.
  Both Vite builds scan shared Tailwind sources explicitly; the redundant
  PostCSS pipeline and legacy `use client` directives are removed.

Earlier browser runs exposed missing admin CSS utilities, a local Wrangler Origin
rewrite, and assertions assuming SSR tag data. These were corrected and affected
projects rerun successfully. Local build warnings about large lazy chunks and
root-relative font URLs remain; generated fonts/assets and lazy PDF/editor loading
work in the browser suite. Workerd also logs occasional broken pipes when browser
navigation cancels requests; these did not fail the final suites.

No remote resource/schema changes or deployment were performed. Delivery consists
of the migration commit and a pull request targeting `develop`, without co-author
trailers. A separate Notion report records the delivery links and validation evidence.
Production CPU time, remote cache propagation, live GitHub OAuth and real R2 upload
behavior remain release verification steps.

### Dependency audit remediation

`@tailwindcss/typography@0.5.20` pins `postcss-selector-parser@6.0.10`, affected by
[GHSA-rj75-hqrm-r3gf](https://github.com/advisories/GHSA-rj75-hqrm-r3gf). A scoped
npm override selects the patched parser `7.1.6` only for typography, preserving
the current typography version instead of accepting the suggested downgrade to
`0.5.4`. Remove this temporary override once the upstream dependency uses a patched
parser, after checking the resulting lockfile and CSS build.

`npm audit` now reports zero vulnerabilities. The full quality gate and production
build pass after the parser change; generated public and admin CSS is byte-for-byte
identical to the pre-upgrade build. This parser is used by the build-time typography
plugin; the advisory is not evidence of the earlier Worker request CPU-limit errors.

### Bundle-size follow-up

The admin entry originally measured 510.37 kB minified (163.83 kB gzip). Loading
the existing Better Auth client only inside sign-in/sign-out actions reduces it
to 479.37 kB (152.16 kB gzip), removing the admin's 500 kB chunk warning. Its
31.09 kB auth module is fetched on demand; no size-warning threshold is raised.

The public PDF renderer remains a large lazy chunk, fetched only on download.
Splitting it merely to remove a warning would not reduce the PDF work or its
total download size. Browser tests verify it stays out of initial page loads and
still generates a real PDF. Server chunks are Worker packaging, not browser
entry downloads; invocation CPU and total compressed upload size remain separate
measurements. See [Vite's chunk warning](https://vite.dev/config/build-options.html#build-chunksizewarninglimit)
and [Rolldown splitting behavior](https://rolldown.rs/reference/OutputOptions.codeSplitting).

After this follow-up, 18 focused Workerd browser tests pass: sign-in errors and
lazy auth loading, session isolation/logout revocation, cross-origin rejection,
upload limits and PDF generation/loading. This includes one new sign-in regression
case; the others recheck previously passing coverage. The full migration baseline
above and this focused run cover 157 distinct passing cases, with one optional R2
case still skipped.
